# 上架路线：微信小程序 / 小游戏 与 苹果 App

本文回答一个问题：**怎样用最少的步骤，把现在的作品变成微信和苹果上的游戏。**
原则与 `LAUNCH.md` 一致：每一步都以真实试玩结果决定是否继续；不把"能打包"说成"能过审"。

---

## 一、先明确三个事实

1. **2D 网页版是最容易上架的资产。** 它零依赖、纯 HTML/CSS/JS，存档走 localStorage。
   微信小游戏和苹果 App（WebView 壳）都可以直接复用它，这是成本最低的路径。
2. **3D 联机版上架最重。** 它需要一台常驻云服务器跑 WebSocket，还要处理小程序
   WebGL 限制、包体大小和真机适配。它应该是最后一步，而不是第一步。
3. **国内"版号"是硬门槛。** 在中国 App Store 和国内安卓渠道上架商业游戏，
   需要版号（ISBN），而版号只能由**企业主体**申请，个人开发者不能申请。
   个人开发者现阶段的选择是：先上海外 App Store（不需要版号）、先上微信小游戏
   （小游戏目前对个人主体开放，但虚拟支付受限），或先注册公司再办版号。

---

## 二、推荐路线（按成本从低到高）

```
第 1 步  网页版上线（现在就能做，0 成本）
        GitHub Pages 已配置，推送后即得在线链接。
第 2 步  微信小游戏（迁移 2D 版，约 1–2 周）
        验证触控、存档、音频；拿到第一批真实玩家数据。
第 3 步  苹果 App · 海外区（WebView 壳，约 3–5 天）
        个人开发者账号 $99/年，无需版号；用 TestFlight 内测。
第 4 步  3D 联机版 App 化（需要云服务器，约 2–4 周）
        Capacitor 壳 + 一台跑 3d/server.js 的云主机。
第 5 步  国内版号与企业化（注册公司后）
        软著 → 版号 → 国内双端正式商业化。
```

每一步都可以停下来。作品在任何一步成立，都不必须走完。

---

## 三、微信小游戏 / 小程序路线（第 2 步）

### 选型
- **小游戏（weapp-game）**：适合本作。Canvas 渲染，无 DOM。2D 版需要把
  DOM 界面改为 Canvas 绘制或改用小程序的 `<canvas>` + 自绘 UI。
- **小程序（WebView 容器）**：可以把现有页面几乎原样塞进 `<web-view>`，
  但 WebView 内音频、存储、横竖屏都受限，且审核会被要求"为什么不做小游戏"。
  叙事游戏用 WebView 容器过审的案例存在，但不推荐作为首选。

### 迁移要点（2D 版 → 小游戏）
| 现有实现 | 小游戏替换 |
| --- | --- |
| DOM 渲染 | 全部改为 Canvas 绘制（UI 层自绘，或引入适配层） |
| `localStorage` | `wx.setStorageSync` / `wx.getStorageSync` |
| Web Audio | `wx.createInnerAudioContext()`（必须用户触摸后启动，与现在一致） |
| 点击/触摸事件 | `wx.onTouchStart/Move/End` |
| 字体 | 系统字体，不加载外部字体 |
| 存档导入导出 | `wx.getFileSystemManager()` 写沙箱文件 |

工作量主要集中在"DOM 界面 → Canvas 自绘 UI"。如果想再省事，可以先只迁移
**一个章节 + 主页**做试玩版，验证留存后再迁移全部。

### 资质与成本
- 主体：个人主体可注册小游戏（每自然人 5 个上限）；企业主体后续做内购更顺。
- 费用：认证费 300 元/年（企业主体）；个人主体免认证费。
- 虚拟支付：iOS 端小游戏长期禁止虚拟支付（苹果要求走 IAP）。策划上
  **不要设计"付费变强/付费解锁章节"**，本作是单次买断制叙事游戏，
  如要收费，优先"免费 + 激励视频 + 外观内购（走微信支付）"。
- 审核：类目选"游戏-角色扮演/剧情"；需要《计算机软件著作权登记证书》（软著，
  个人/企业均可办，约 1–2 个月）和隐私协议。版号目前小游戏不强制（以当时政策为准）。

### 步骤
1. 注册小程序账号（mp.weixin.qq.com），选择"小游戏"类目，完成主体认证。
2. 下载微信开发者工具，建空小游戏项目。
3. 迁移：先搭 `game.js` 入口 + Canvas 适配层 + 存储/音频封装，再逐屏迁移。
4. 真机预览（开发者工具 → 真机调试），重点验证：触摸、音频解锁、前后台恢复、全面屏。
5. 体验版发给 10–20 个玩家试玩，收集数据。
6. 提交审核 → 发布。审核一般 1–7 天。

## 四、苹果 App 路线（第 3 步：先海外区）

### 方案 A：WebView 壳（最快，推荐先做）
- 用 **Capacitor**（或 PWABuilder/Tauri）把 2D 版网页包成 iOS App。
- 网页部分几乎不用改；要做的是：图标、启动屏、 safe-area、横竖屏锁定、
  `WKWebView` 内的音频策略（首次触摸后启动，现有逻辑已兼容）。
- 费用：Apple Developer Program **$99/年**（个人即可）。
- 海外区**不需要版号**；国内区需要（见第 5 步）。
- 内测：TestFlight（最多 1 万名测试者）。
- 审核注意：元数据要如实描述"原创虚构叙事游戏"；不要提到其他游戏名；
  隐私清单（Privacy Manifest）必填；如接入分析 SDK 需声明。

### 方案 B：3D 联机版真 App（第 4 步）
- 同样的 Capacitor 壳包 `3d/` 目录；但 `3d/server.js` 需要一台云服务器
  （任一小规格 VPS，2C4G 即可带几十人同时在線；建议国内+海外各一台，或先用海外）。
- 包体：three.min.js 约 650KB，加上资源远低于 4GB 上限，无压力。
- 网络：WebSocket 用 `wss://`（Let's Encrypt 免费证书）。
- 审核：需要说明联机用途；测试账号要提供（如果做账号系统）。

## 五、国内正式商业化（第 5 步）

顺序不能乱：**软著 → 公司主体 → 版号 → 双端上架**。

1. **软著**：中国版权保护中心，个人也能办，约 1–2 个月出证。越早办越好，
   小游戏审核、版号、上架都会用到。现在就可以以现有代码申请。
2. **公司主体**：版号必须企业申请。注册公司后，小程序/小游戏主体从个人迁移到企业。
3. **版号（ISBN）**：通过省级出版管理部门报国家新闻出版署，周期约 3–6 个月，
   需要企业主体、软著、运营方案、防沉迷（实名 + 未成年人时段限制）与
   "游戏内容自审报告"。本作无内购付费点，过审内容风险低。
4. **双端上架**：iOS 国区 + 国内安卓渠道（华为/小米/OPPO/vivo/应用宝）。

## 六、合规红线（提前避开）

- **不要**在任何平台素材里写"超过魔兽世界"之类的对比宣传——苹果审核条款
  3.1 与国内广告法都不允许，且与作品气质不符。用试玩数据和玩家评价说话。
- **iOS 虚拟支付**：iOS App 内解锁内容必须走 IAP（苹果抽 15%/30%）。
  设计上建议"免费下载 + 激励视频 + 非付费内容完整"，规避支付合规复杂度。
- **未成年人**：国内版必须接入实名与防沉迷；小游戏同样有未成年人时长限制。
- **隐私**：两个平台都要隐私政策；本作不采集个人信息，是最有利的过审点。
- **AI 素材声明**：片尾已注明"画面由 AI 生成"，各平台如要求 AI 内容声明，
  按平台表单如实填写。

## 七、一张时间表（参考）

| 阶段 | 动作 | 周期 |
| --- | --- | --- |
| 现在 | 推送到 GitHub Pages，收集试玩反馈 | 1 天 |
| 第 1 个月 | 办软著；同时迁移微信小游戏试玩版 | 并行 |
| 第 2 个月 | 小游戏提审发布；注册 Apple 个人账号，Capacitor 壳上海外区 | 2–4 周 |
| 第 3 个月起 | TestFlight 内测 → 海外 App Store 上架 | 1–2 周审核 |
| 之后 | 3D 联机上云；企业化与版号 | 视试玩数据 |

**判断标准**：只有网页版/小游戏的完读率和"想再玩一条线"的比例足够高时，
才值得投入 3D 联机和版号的成本。数据不够，就继续打磨 2D 内容——那是本作
真正的护城河。
